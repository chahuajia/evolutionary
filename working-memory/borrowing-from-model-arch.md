## 假设 1：`acceptance rate` 是派工账本缺的那个数

**借自**：推测解码。草稿模型提议、目标模型验证；
**接受率（accepted / proposed）是决定加速的主导变量**，所有相关工作都指向它。

**映射**：父 = 目标模型，子 = 草稿模型。而我们的账本只记：

```
loop 头：dispatched=N recovered=M      # N=M 才算收口
```

**`recovered` 回答的是"有没有回音"，不是"回音经受住审查没有"。**

**本地证据**：有数据没算过。wave42 两路**都是 accepted（我直接 merge，零重做）**；
但更早的波次有没有 reworked，没人记。

**怎么验**（成本：每波多记 3 个数字）：
```
accepted = 子产出直接合入，父零修改
reworked = 父做了修改才合入
rejected = 弃用重做
```
跑 3–5 波后看 `accepted / dispatched`。若长期 > 0.8 → 现状够用；
若 < 0.5 → 派工本身在浪费（brief 不对，或切片选错）。

**若成立**：账本加这三个字段；`extreme` 的派出会计从"收发对账"升级为"接受率"。

**反例警戒**（论文实测）：**接受率高 ≠ 更快** —— 1.5B 草稿 96% 接受率却比
0.5B 的 74% 更慢（草稿延迟吃掉收益）。映射：**慢而好的子代理可能不如快而够用的**；
且**父的验证成本要算进去**，不能只算子代理的。

---

## 假设 2：症状表是"廉价查找面"，不该往里面塞推理

**借自**：V4.1-Flash 的 **Engram / N-gram 条件记忆模块** —— 196B 参数构成
**独立的查找表池**，可卸载到内存，让相关知识被**廉价地 surface 出来**，
**不进注意力/推理路径**。

**映射**：这正是症状表的设计，且它验证了一个**已在做**的选择：

- 知识存储**分离**出推理路径 → 我们也不该把 KB 全量载入上下文
- 它是 **N-gram（字面序列匹配）** → 症状表就是"看到 X → 读 Y"的字面匹配

**本地证据（间接，但存在）**：
`AGENTS.md` 手写症状表实测命中率 **2/4**，而 catalog 关键词检索 **0/4**。
当时的解释是"按症状组织比按目录组织好"。**这里的解释更具体**：
**字面匹配本来就该比语义目录检索快** —— 因为它是查找，不是推理。

**怎么验**（低成本）：构造 10 个真实症状，分别走症状表 / catalog 关键词，
记命中数与耗时。若症状表持续显著更优，则把**更多**路由费从 catalog 移到症状表。

**若成立**：`AGENTS.md` 症状表是 KB 的**主存储面**（不是"补充"），
catalog 降级为纯目录。**这与现状一致，但理由换了** —— 现状是"实测更准"，
新理由是"它是查找表而 catalog 是检索"。

**反面**：不要因此去**扩充**症状表 —— 它之所以廉价，是因为它**小**。
（890 bytes/token 的 KV 缓存同理：代价在 resident 的那份。）

## 假设 3：KB 参与该有三档（Full / Reindex / Reuse），不是两档

**借自**：`Compressed Sparse Attention 2` —— **每个注意力层跑在
Full / Reindex / Reuse 三种模式之一**，跨层共享 KV 与索引器状态。
核心观察：**不是每层都需要全算。**

**映射**：`usage-guide` 现在是二元的（查 / 不查）：

| 模式 | 模型 | KB |
| :--- | :--- | :--- |
| **Full** | 从头算注意力 | 深度检索（症状表 → catalog → 读 2–3 条） |
| **Reindex** | 重建索引状态 | 只重新路由（扫症状表，不读条目） |
| **Reuse** | 复用已缓存的 KV | **沿用本会话已确立的结论，不重查** |

**缺的是 Reuse。** 长会话里反复重新推导已确立的东西 = 把算力花在重算上。

**本地证据**：无。这是纯假设。

**怎么验**（观察，不必实验）：下次长会话时，标出"我重新查了一件本会话已经确定过的事"
的次数。若 > 3 次 → 真问题；若 ≈ 0 → 假设不成立，别写。

**若成立**：`usage-guide` 的"该不该查"从二值改成三值，并写明 Reuse 的判据：
**"本会话内已确立的结论 → 沿用，只在被新证据挑战时回到 Reindex。"**

---

## 假设 4：条目的"饿死"和"孤岛"是两回事，我们只测了后者

**借自**：MoE 路由坍塌 —— naive top-k **过度选择少数专家、饿死其余**；
被饿死的专家拿不到梯度，**永久锁死**。

**映射**：`collab retire --candidates` 找的是**孤岛**（入度 0 **且** 出度 0）。
但还有一类：

> 一条条目**被链接**（有入度）却**从没被症状表路由到**（零路由）

它不会出现在孤岛清单里，却同样在腐烂。

**本地证据**：**已算过（2026-09-19）**。

```bash
# 从 AGENTS.md 的**症状表表格行**抽被路由的 id（排除 ## 关联 那串平铺双链）
# 与 catalog 的 active 条目集合做差集
```

结果：

```
症状表表格行        32
catalog active     121
被症状表路由到       25
**从未被路由**      96  (79%)
   其中带 trigger    86  ← 仍可被 catalog 关键词命中
   其中无 trigger    10
   类型分布：pattern 37 · skill 32 · adr 10 · agreement 9 · workflow 5 · integration 3
```

### 但这个数**不能**直接读成"96 条是死的"

- 症状表**故意只有 25 行**（它的价值就在小 —— 见假设 2 的"代价在 resident 的那份"）
- 86/96 带 `trigger`，**仍可被 catalog 关键词检索到** —— 它们不在快路径上，但**可找到**
- "可找到" ≠ "被读过"。**我们不知道它们有没有被读。**

### 真正的发现：缺的不是"清理 96 条"，是**缺一把尺**

`meta/pruning-policy.md` 第 96 行写着：

> `引用计数 = 0 且 > 6 个月` → 标记-清除候选

**而全库没有"引用计数"这个仪器。** 这正是该政策自己承认过的
「未被引用需要测量，而从未有人测量过」。

我们建的 `retire --candidates` 是**图结构**的（孤岛：入度 0 **且** 出度 0），
**不是读取行为**的。**两回事。**

⇒ 假设 4 的真产出**不是"发现 96 条坏条目"，是"发现少了一把尺"**。

**若成立**：该做的是**读追踪**（`collab read` / MCP `collab_read` 记一次），
不是清理那 96 条。**在没有尺之前，"该不该清"不可判定。**

**反例警戒（这条很重要）**：MoE 文献明确警告 ——
**强制负载均衡会把专家同质化，实测见过 99% 输出相似**；辅助损失系数太大会毁掉专门化。

映射：**不要为了"每条都被用到"而强行造引用。**
少数承重条目被高频路由是**对的**。要抓的是"**从来没被读过**"，不是"路由得不均匀"。

## 明确不采纳的（只列，避免后人重走）

| 类比 | 为什么不采纳 |
| :--- | :--- |
| KV 缓存 890 bytes/token → "把路由表压小" | 听着顺，**没有可验的推论**。症状表本来就 25 行。 |
| 非对称 CED（读 8B / 写 16B）→ "读该更便宜" | 方向对但**没有可执行动作** —— 我们已经"不读"了。 |
| FP4 量化 → "压缩条目正文" | 串味：那是模型权重的问题，不是知识表示的问题。 |
| MTP / 多令牌预测 | 找不到对应物，**不硬凑**。 |

## 总方针

**四条都不入库，先验。** 判据：

- 假设 1、4 有数据，**一个脚本/几个字段就能验** → 优先
- 假设 2 有间接证据，**10 个症状的小实验** → 次之
- 假设 3 无证据，**只观察不实验** → 最后，且很可能不成立

**验完再谈入库。** 每条入库时都要能回答入库门槛那句：
「不读它，模型会照着本地哪个模式写错？」
—— 如果一条借来的洞察答不出这句，它就只是一段漂亮的类比。

## 意外收获：这次测量本身压出了一条更硬的结论

把假设 4 算完之后回头看，本会话**四次**"建仪器"，四次都撞出真东西：

| 建了什么仪器 | 撞出了什么 |
| :--- | :--- |
| 修 2 个预存在的红测试 | 根因是「种子按 context 跑一次 + H2 全 JVM 共用」，**不是测试写错** |
| 写换电原子性测试 | 注释声称"同事务双写"而全仓无 `@Transactional` —— **真数据错** |
| 查 `enforced` 路径存在性 | 我自己写的路径**根本不存在**（validate 却报 0 issue） |
| 数"从未被路由的条目" | `pruning-policy` 的「引用计数 = 0」**没有仪器** |

而**同期所有"没有仪器的政策"，一条都没执行过**：

| 政策 | 状态 |
| :--- | :--- |
| `引用计数 = 0 且 > 6 个月 → 标记-清除候选` | **从未测量过**（政策自己承认） |
| `6 个月未被引用 → dormant` | 从未执行（v4.1.3 已废，理由是"从未有人测量"） |
| 代谢配额「新增 3 → 处理 1」 | 从未执行（codex 实测：新增 ~12，处理 1） |
| 基于时间的修剪规则 | 从未执行 |

### 结论（**已找到反例，因此修正过一次**）

初版结论是二分法：

> ~~能测量 → 执行且发现问题；不能测量 → 从未执行~~

**去找反例，找到一个，而且它很重要：**

| 证据 | 时间 |
| :--- | :--- |
| `check-freshness.mjs` 写入 | **2026-09-16 22:27**（`84a849b`） |
| 接进 `.husky/pre-push` | **2026-09-18 22:35**（`8c221a9`） |

**中间两天，仪器存在但从未运行。** 而一跑就立刻发现 3 个仓里 **2 个已烂**
（collaboration 落后 21 提交、evolutionary 未登记）。

⇒ "有仪器" **不等于** "被执行"。**仪器必须接线才算存在。**

### 修正后的三分法

| 状态 | 结果 | 本地证据 |
| :--- | :--- | :--- |
| **无仪器** | 从未执行 | `引用计数`（无仪器）、代谢配额、时间修剪规则 |
| **有仪器、未接线** | **也未执行** | `check-freshness` 写了 2 天没跑 |
| **有仪器、已接线** | 执行，且**立刻发现问题** | 接线当天就抓出 2/3 仓烂 |

**"写了一个脚本"不是仪器。** 这与本会话另一处观察是同一件事：
唯一被 `check-freshness` 盯着的仓恰好是唯一新鲜的 —— **机制只管它被安装的地方**。

### 它比借来的四条硬

因为它是**本地证据**，不是类比。而且它给 `policy-without-mechanism`
补上了机制的定义：**"机制"的实质可能就是把政策接到一个会亮的东西上。**

### 留给下一个人的验证

- 找"**已接线但从未触发**"的政策 → 会证伪第三行
  （注意区分：接线了但条件从未满足 ≠ 从未执行 —— 前者证明它**在工作**）
- 找"**无仪器却执行良好**"的政策 → 会证伪第一行

两轮找不到反例 → 够格入库（且很可能值得升到约定层）。

# 第二批：从 **multi-agent 架构** 借什么（2026-09-19）

**来源**：Cursor *Scaling long-running autonomous coding*、yage.ai 多 agent 失败研究、
OKF 记忆生态综述。

> ⚠️ **保真度声明**：WebFetch 被网络策略挡了，本批材料是**搜索引擎摘要，非原文**。
> 置信度低于第一批（第一批至少拿到了官方文档）。引用时按"听说"对待。

## 已本地验证并实现（不是假设）

**`enforced` 可以静默失效。** 对照 OKF/Kage 的
「来源漂移则**撤回**（withheld），而非静默返回过期内容」——
我们实测：`enforced` 指向不存在的文件时 `collab validate` 报 **0 issues**。
⇒ 已实现 `collab validate --check-enforced`（`1fb7c3d`）。

**这一条是本批唯一的已验证项。以下才是假设。**

## 假设 5：我们**没有 Judge**

**借自**：Cursor 的 **Planner / Worker / Judge** 流水线 —— judge 在每轮末尾
决定是否继续，**下一轮从 fresh state 开始**；文中明确把
**periodic fresh starts** 列为对抗 drift / tunnel vision 的手段。

**映射**：我们有 Planner（父）与 Worker（子代理），**没有 Judge**。
而我们的 drift 症状是**有记录的**：证据 4（父把需判断当停机）、
证据 5（派工幻觉 + WM 不刷新）。

**假设**：这两个症状与"没有独立判断环节"是同一个洞。

### ⚠️ 先跑了零成本版，**假设需要修正**（2026-09-19）

**原计划的验法**：每波收口前，父**自己**回答「这一波真的推进了吗？」并写下答案。

**跑完发现这是同义反复。** 「问有没有推进」**按构造**能识别「没推进」——
问题从来不是问不出来，是**答的人会不会诚实回答**。

而证据 4 已经给了答案：父当时写的是「下一刀需判断」，
**说明它知道没推进，并且合理化了**。⇒ **自问式 judge = 已有的自我评估，
而它已经失败过一次。**

**Cursor 的原文其实说对了**：*a **judge agent** determines whether to continue* ——
是 **agent**，不是父自问。

### 修正后的假设 5'

> **独立的**第三方环节——不是父自问——才有可能抓住"自以为推进"。

**但这立刻撞上两个已有约束**：

| 约束 | 冲突 |
| :--- | :--- |
| 证据 6：小切片派工**负吞吐**（worktree 30–70s + Task 常 Timeout） | judge 是个小活 → 按 v11 的派工成本门槛，**不该派** |
| 证据 4：父的自我评估会合理化 | 不派独立 judge → 又退回自问，等于没有 |

**所以真正的问题是**：judge 要**独立**才有用，要**便宜**才划算 ——
而我们现有的派工机制恰好**既贵又不可靠**。

**怎么验（修正版）**：judge 未必要"一个 agent"。可考虑
**把判断交给机器**：收口前跑一条**可执行的检查**（如 `git log` 自上个 wave 起
有无非 `docs` commit + 目标测是否绿），用它**否定**"本波推进了"的主张。
成本 ≈ 一条命令，且**不会合理化**。

> 这条把假设 5 从"加一个角色"改成了"**加一条检查**" ——
> 与 `policy-without-mechanism` 的结论一致：**要的是仪器，不是角色**。

**仍不实现**：先看这条检查在**真实停滞**时会不会亮（下一波真卡住时验），
而不是现在建流程。

**反例警戒**：Cursor 自己说 **"the right amount of structure is in the middle"**、
**"many improvements came from removing complexity"** —— 我们刚加 v11。

## 假设 6：**"父收口"可能是反模式**

**借自**：Cursor 试过加 **"integrator" 角色**做质量把关与冲突解决，
结论是 **created more bottlenecks than it solved** —— worker 本来就能处理冲突。

**映射**：我们刚花几轮**加固"父收口"**（撞车处理、冲突合并、验绿）。
Cursor 说那个角色是反模式。

**但**：不能直接套 —— 他们的 integrator 是**额外**角色（第三类 agent），
我们的父同时是 planner，且只有 2 个 worker。

**怎么验**（观察，不必实验）：
下一波派工时**故意让两个 worker 直接协商**一个冲突点（父不介入），
看结果：能自己解决 → 父收口确实多余；解决不了/跑偏 → 父收口承重。

**若成立**：`extreme` 的「worktree 隔离 + 父收口」应当重新表述为
「隔离是为**并行**，不是为**由父仲裁**」。

## 假设 7：**上下文隔离的度**

**借自**（yage.ai）：multi-agent 的核心挑战是**"上下文隔离的度"**；
按人类社会分工拆 sub-agent **可能降低能力**，因为 **LLM 是通才**（不是专才）。

**映射**：我们的 brief 是**极窄**的指令（"照着某个文件抄"）。
假设是：**再窄一点，模型能力用不上；宽一点，它又能自作主张。**

**怎么验**（对照，成本中）：
同一个切片派两次 —— 一次给"照抄 X"的窄 brief，一次给"目标 + 约束"的宽 brief（留判断空间），
比产出质量与返工。

**反例警戒**：这与我们已确立的「小切片主树父写」有张力 ——
如果宽 brief 更好，那"窄指令"这条经验就要重新审视。

## 已与我们记录**吻合**的一条（旁证，不是新假设）

yage.ai 引用的失败研究：**79% 的 multi-agent 失败源于 spec 与协调，
基础设施只占 ~16%**。

我核对了我们的失败记录：

| 失败 | 归类 |
| :--- | :--- |
| 证据 4：父把需判断当停机 | 协调 |
| 证据 6：小切片派工负吞吐 | 协调 / 设计 |
| 我那 4 条写错的规则 | **spec**（我自己的推理） |
| 半错的刀（"纯壳就该 RSC 化"） | **spec**（未核实因果） |
| 证据 5：Task 创建超时 | 基础设施 |

**协调 + spec 占压倒多数，基础设施只有 1 条。** 吻合。

⇒ 若这个比例成立，**继续投基础设施（worktree、hook、仪器）的边际收益低于投"弄清规格"**。
这与本会话"装仪器"的路线**有张力**，值得记着。
