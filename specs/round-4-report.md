## 设计决策三问（P3）

### 决策：可用性不变量放在 `swap`，不放在 `create`

| 问 | 答 |
| :--- | :--- |
| 没有它会怎样 | 空站 / 全在充电的站无法被建模，配电池与真实运营状态被构造器挡掉 |
| 收益 | 与规格一致：「至少 1 块可用才能**换出**」，不是「站必须随时可换」 |
| 成本 | 调用方必须处理换电失败；类型系统不保证「随时可换」 |

来源：症状表 → `S13`（跨对象不变量由聚合操作守）。

### 决策：换出电池离站；换进以 CHARGING 入站

| 问 | 答 |
| :--- | :--- |
| 没有它会怎样 | `IN_USE` 留在 `batteries()` 会把「在站库存」与「曾属于本站」混为一谈 |
| 收益 | `batteries()` = 当前在站；与 `BatteryStatus.IN_USE`「已被取走」注释一致 |
| 成本 | **推断**，规格未写清单怎么变 —— 写进诚实记录 |

### 决策：不引入 Spring / 不用 `Result` 类型

| 问 | 答 |
| :--- | :--- |
| 没有它会怎样 | 领域层被框架拖下水；或引入库里没有的 `Result` 类型 |
| 收益 | 继续可用 `mvn test` 纯测领域；与既有 `Battery` 异常风格一致 |
| 成本 | 偏离 `S13` 字面的 `Result` —— **E6 再现**，记为未关闭暴露 |
